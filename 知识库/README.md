# 冰灵锐目 法规知识库

本目录收录「广告招牌」「食品标识」两个判别域现行有效法律法规的权威全文,作为拍照识别 / OCR 后判别的法规依据。

每份 markdown 含:

- 发文字号、发文机关、通过日期、施行日期、当前有效性
- 官方 URL(优先 `flk.npc.gov.cn` / `samr.gov.cn` / `openstd.samr.gov.cn` / `gov.cn`)
- 原文
- 适用判别要点(可由 OCR 后关键词触发的判别条目)

## 目录

- [`广告业务/`](广告业务/) — 广告招牌域 (7 部)
- [`食品标识/`](食品标识/) — 食品标识域 (6 部)

## 与代码层的关系

本目录与 `app/src/main/assets/rules/<domain>_rules.json` 是 **1:N 关系** — 一份法规可能对应多条规则。每条规则的 `regulation` 字段就是 markdown 文件内的具体条文引用,`lawText` 字段摘抄自对应 markdown 段,`rule.id` 用 `<domain>_<article>_<short>` 命名(例 `ad_signage_art9_abs`、`food_gb7718_nozero_add`)。每次增加规则都可回溯到知识库文件。

`适用判别要点` 段是规则 JSON 关键词的真正出处。`原文` 段是供人查证、对照条文时使用,代码层不直接读取。

**为什么有些是 stub?**

`WebFetch` 在沙箱内对中国政府官方站点 (`flk.npc.gov.cn`、`samr.gov.cn`、`gov.cn`、`openstd.samr.gov.cn`) 大多被网络策略拦截返回 `Unable to verify if domain is safe to fetch`。少数能成功(主要走 `gov.cn` 上挂载的 PDF 直链)的已收录为 `全文 ✓`;其余按"未实际检索到原文不伪造文本"的硬性约束,`原文` 段以 `[未检索到全文]` 占位,附章节骨架 + 数据采集说明 + 适用判别要点。

## 同步说明

- **代码层 (rules JSON) 不依赖 markdown 完整收录** — 每条规则的关键词集合已经在 markdown 的「适用判别要点」段独立列出, 规则层不读取 markdown 原文。所以 stub 状态不影响 app 的判别功能。
- **人工回填路径**: 未来 PM 在可访问外网的浏览器内打开每个 stub 的「官方 URL」,把正文复制回对应 markdown 的 `## 原文` 段即可。章节骨架已就位,文字直接替换。
- **新增法规时**: 按 `知识库/<域>/<法规名>.md` 新建文件, 按本目录 schema 填写 metadata + 原文 + 适用判别要点, 然后在对应 `<域>_rules.json` 中按 `适用判别要点` 添加 rule, `rule.id` 用 `<域>_<条款编号>_<short>` 命名。
