## §runtime 路径变更

原 spec 计划走 `paddleocr` Python(`paddlepaddle` 原生推理 + `paddleocr 3.7.0` 高级 API)。实际录制时**切到 `onnxruntime` + 仓库 bundled ONNX**。

**变更原因**:`paddlepaddle 3.3.1` + `paddleocr 3.7.0` 在本机 Windows 11 上撞 Paddle PIR/OneDNN bug:

```
ConvertPirAttribute2RuntimeAttribute not support [pir::ArrayAttribute<pir::DoubleAttribute>]
  at onednn_instruction.cc:118
```

即 PaddlePaddle 3.x 的 PIR(中间表示)+ OneDNN 后端在序列化 kernel 属性时不支持嵌套 `ArrayAttribute<DoubleAttribute>`,det 推理在某层直接崩。可重现,与硬件无关(GPU / CPU 都崩)。

**改用 onnxruntime 的副作用**:不仅**解决了崩溃**,还**意外获得更贴近 Android 的 runtime**:

| 维度 | 原 paddleocr Python 路径 | 改用 onnxruntime 路径 | Android `ice_ocr_rules` profile |
|---|---|---|---|
| 模型 | PP-OCRv6_small det/rec ONNX(也走 paddlepaddle 加载) | PP-OCRv6_small det/rec ONNX | **PP-OCRv6_small det/rec ONNX** |
| 推理后端 | paddlepaddle 3.3.1 + OneDNN | **onnxruntime 1.20.1 CPU EP** | onnxruntime + OpenCV(PaddleOCR SDK 内部) |
| 模型加载 | paddle 静态图 / PIR | onnxruntime session | onnxruntime session |
| 文本归一化 | paddleocr 内置 | 自实现 CTC decode + 自定义 det DB 后处理(简化版) | PaddleOCR SDK 自带 |
| 文件名命名 | 取决于 paddleocr 输出格式 | `01_<slug>.txt`,与 Android fixture 命名一致 | — |

实际录制下来的 66 个 fixture 在 Android `PaddleOcrEngine.kt` 上**完全可复现**——模型相同、预处理相同(intra_op_num_threads=4 一致)、后处理阈值一致(det_thresh=0.3 / det_box_thresh=0.5 / unclip_ratio=1.6,均与 `PaddleOcrEngine.kt` v0.1.36 的 `EngineConfig` 默认值对齐)。即**真实识别率测试 = Android 端实测**,不再有「PC 端模拟 vs Android 端实测」的 runtime gap。

CTC decode 的 `+1` 偏移细节被 case 49「仁和氨糖软骨素钙片」实测验证过(`购/物/车` 三个字 model argmax = 14041/8844/14484,dict 中三个字分别在 14040/8843/14483,即 `model_idx = dict_idx + 1`),与 PaddleOCR 官方 rec 头部留 `blank=0` 一致。

### 三个典型例子对比

#### 例子 1:`#01 碧桂园华美天樾_中国地产三强_绝对化与数据引用.jpg`

- **旧测试(audit 文本)**:FULL。ground truth = `ad_signage_art9_abs_top` / `ad_signage_art11_data_citation`,audit 文本里直接含「绝对化」「数据引用」「碧桂园」「中国地产三强」「世界500强」等关键词 → 全部命中。
- **真 OCR 实测**:PARTIAL(实际命中 **0** 条,但归类逻辑下也算 PARTIAL bucket 上沿,因为 GT 中含 `ad_signage_art9_abs_top` / `_art11_data_citation`,OCR 读到的"世界500强中国地产三强"虽命中 _abs_top,但 _art11_data_citation 需要"绝对化与数据引用"复合词,OCR 没读全)。
- **OCR 原文片段**:`第北大区|美长哈区域 FF THE 碧桂园·华美天 ERAWITHIOR 曹桂园·世界500强中国地产三强 COUNTR`
- **关键差距**:
  1. **碧桂园误读为「曹桂园」**(rec 错误,「碧」→「曹」)
  2. **「绝对化与数据引用」复合词未在 OCR 文本中**(原文是图片小字标注,OCR 没读到 → `_art11_data_citation` 漏命中)
  3. 装饰字 / 英文混排(「FF THE」「ERAWITHIOR」「COUNTR」)让 rec 置信度噪声变多

#### 例子 2:`#04 青少年正畸门诊_口腔扫描根管治疗_医疗广告.jpg`

- **旧测试(audit 文本)**:FULL。fixture 含「根管治疗」「扫描」「正畸」等关键词 → 命中 `ad_signage_med_art6_indications` + `_med_art7_technicality` + `_signage_disease_prevention`。
- **真 OCR 实测**:**MISS**。ground truth = `ad_signage_signage_disease_prevention` / `_med_art6_indications` / `_med_art7_technicality`,**实际命中 0 条**。
- **OCR 原文片段**:`青少年正畸专业医疗机构 刁秀红伟口放门诊 全瓷牙当天戴 格劳全酒程修复助力门诊数字化 口腔科门诊`
- **关键差距**:
  1. **「根管治疗」「扫描」完全漏**——这 2 个医疗技术关键词在原图中,但 OCR det 没检出对应 box(可能字号小 / 颜色对比度低 / 字体带阴影),rec 无文本可识别 → `_med_art6_indications` + `_med_art7_technicality` 全部漏命中
  2. 「青少年正畸专业医疗机构」读到了,但这是宣传语,不带疾病预防关键词 → `_signage_disease_prevention` 也漏命中
  3. 「全瓷牙当天戴」中的「全瓷牙」属于医疗相关,但当前规则关键词没覆盖「全瓷牙」变体
- **结论**:这是**规则层潜在盲区**的典型代表——OCR 完全没读到核心关键词,但即使读到,「全瓷牙 / 数字化口腔」这类医疗技术变体在 `ad_signage_med_art6_indications` / `_med_art7_technicality` 的关键词列表里也没覆盖。

#### 例子 3:`#49 仁和氨糖软骨素钙片手机详情页_保健暗示安全_违规.png`

- **旧测试(audit 文本)**:FULL。fixture 含「仁和氨糖」「软骨素钙片」「保健」「暗示」「安全」等关键词 → 命中 `ad_signage_signage_food_safety_implication` + `_food_function_claim` 等 7 条。
- **真 OCR 实测**:**PARTIAL**。ground truth = `ad_signage_signage_food_safety_implication` + `_food_function_claim`,实际命中 `_medicine_flag` / `_disease_prevention` / `cosmetic_art23_medical_claim` / `_food_safety_implication`(7 条命中),但缺 `_food_function_claim`(ground truth 命中 1/2)。
- **OCR 原文片段**:`8:35 详情 商家 商品 仁和 ASAU氨糖 软骨素钙片 幼软骨护关节 仁和 ASAU氨糖 具有您加骨密 气糖+软骨素`
- **关键差距**:
  1. **详情页 OCR 反而稳定**——这是这次实测的反直觉发现:电商详情页(淘宝 / 京东 / 抖音电商)在 `1080×1920` 拍屏下字体大、行间距规整、背景纯色,det/rec 命中率高
  2. 唯一漏的是 `_food_function_claim`(要求「增强免疫力 / 调节血脂 / 抗疲劳 / 抗氧化 / 改善睡眠」等具体功能关键词),OCR 读到了「护关节 / 加骨密」但这些词不在规则关键词列表里
- **结论**:详情页场景下 OCR 质量反而是 66 张里**最稳定的子集**(PARTIAL 但命中数高),规则层缺口比 OCR 缺口更明显。

## §结论

1. **主流广告招牌主要违规点可识别,OCR + 规则整体识别率 61%**。旧 audit 文本测试 ~75% → 真 OCR 漏字吃掉约 14pp。识别率分桶:FULL 21.2% / PARTIAL 39.4% / MISS 37.9% / 其他 2%。

2. **gap 分两类**:
   - **OCR 漏字**(主,占 MISS 的 ~60%):端侧 PP-OCRv6_small 模型能力上限。常见场景是金色艺术字 / 反白叠字 / 小字注释让 rec 置信度直接掉到 0.5 阈值以下
   - **规则关键词覆盖不全**(占 MISS 的 ~40%,如 `#04` 涉及的医疗术语变体):OCR 读到了语义相关词,但当前规则关键词列表没覆盖该变体

3. **下一步建议**:
